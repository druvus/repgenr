# Scaling and bias audit

Status: measurement in progress — n=5000 tier and bias experiments B1/B2/B4/B5
land last; sections marked PENDING will be filled from `benchmarks/results/`.

This document reports, per pipeline step: the available tool alternatives, how
each scales with genome count (measured wall time and peak memory), whether a
project can start from 1000 or 5000 genomes, and how genome similarity
structure — in particular over-represented genotypes such as an outbreak clone
block — biases the results. Methods and raw numbers live in `benchmarks/`
(see `benchmarks/README.md`); mechanism claims cite source locations. The
detailed per-stage SWOT and gap analyses are in [swot-derep.md](swot-derep.md),
[swot-phylo.md](swot-phylo.md), and [swot-viral.md](swot-viral.md).

## Benchmark design

Synthetic sets generated by `benchmarks/genomegen.py` (seeded, stdlib):

- `balanced_n`: distinct species-level clusters (~95-97 percent inter-cluster
  ANI, 99.5-99.9 percent intra), no over-representation. balanced_100 holds 2
  true clusters; balanced_1000 holds 20.
- `clonal_n`: 40 percent of genomes form one near-identical clone block
  (>=99.99 percent ANI, skani-validated at 99.98-99.99), the rest diverse
  background — the outbreak-plus-context shape.
- Accession order (`clustered` / `interleaved` / `random`) is a first-class
  variable because several selection mechanisms depend on alphabetical
  filename order.

Hardware: 11-core arm64 macOS, 8 threads per run, data on external exFAT
storage. Measured with `/usr/bin/time -l` (max RSS). Caveats: synthetic
genomes are mutated copies of a random 2 Mb ancestor — exact for k-mer/ANI
tools, a lower bound for whole-genome aligners, unrealistic for gene-model
tools. All numbers below are from `benchmarks/results/cells/*.json`.

### Findings

1. **Found and fixed (#127, #128): the sourmash adapter's `--secondary-ani`
   thresholded Jaccard similarity, not ANI.** At the same nominal 0.99
   threshold, skder and galah recovered the true clustering exactly
   (ARI 1.00 in every cell) while sourmash left every genome a singleton on
   the balanced sets (ARI 0.00) and merged only the near-identical clone
   block on the clonal sets (ARI 0.54-0.90). Verified directly: a genome
   pair at 99.57 percent ANI (skani) has k=31 Jaccard 0.796 — far below the
   0.99 cut — while the ANI estimate for the pair is 0.9961. The fix
   converts both back-ends to the ANI scale with one formula: sparse keeps
   pairs by `containment^(1/k)` from branchwater's edge list (prefiltered
   at `threshold^k` to stay sparse), dense converts the Jaccard matrix via
   `(2j/(1+j))^(1/k)` — computed in the adapter rather than with `compare
   --ani`, which reports 0 for tiny sketches. Post-fix, all 12 sourmash
   cells score ARI 1.00 (table above), sparse and dense agree at every
   size, and sourmash-sparse is the fastest correct dereplicator measured
   at n=5000 (335 s, 0.7 GB).
2. **Representative identity is tool- and backend-dependent on clone blocks**
   (B1, `benchmarks/results/bias_b1.json`; clonal_50 under three accession
   orderings). galah crowns the alphabetically first clone member in all
   three orderings — its choice tracks filename sort position exactly.
   sourmash-sparse crowns the alphabetically first member in two of three
   orderings (greedy first-seen assignment). skder picks by its own
   aggregate-ANI criterion (a different member in each ordering; within a
   near-identical clone block that choice is effectively arbitrary). The
   sparse and dense sourmash backends crown different members on the same
   input (clonal_100: g000000 vs g000034; clonal_1000: g000010 vs g000384).
   Practical consequence: which outbreak genome becomes "the representative"
   depends on the tool, the backend, and the accession naming — not on
   content quality.
3. **Chunked dereplication is input-order dependent by construction** — the
   sorted genome list is sliced into contiguous chunks
   (src/repgenr/stages/dereplicate.py), so a clone block that sorts together
   is handled by one chunk, while a scattered one meets every chunk's local
   threshold independently. Measured effect: PENDING (B2, heavy tier,
   clustered vs random accession order at n=5000).
4. **`--target-reps` bisects a step function on clonal sets.** Intermediate
   targets are unreachable and the search silently returns the closest
   achievable count (max 12 iterations). Pinned by
   `tests/unit/test_bias_regressions.py`.
5. **`--reduce species|genus` keeps the over-represented genotype.** The
   keeper rule (largest existing cluster) selects the clone block's
   representative by construction and folds diverse lineages under it.
   Pinned by `tests/unit/test_bias_regressions.py`.
6. **Memory scales with n for skder/galah** (about 1.1-1.5 GB at n=1000
   against roughly 200 MB at n=100 — an approximately linear-or-worse trend
   to confirm with the n=5000 tier); sourmash's sparse path stays flat
   (about 250 MB at n=1000).

## Phylogeny

### Measured scaling

| Cell | wall | peak RSS | outcome |
|---|---|---|---|
| mashtree, 100 genomes | 9 s | 69 MB | 100-leaf tree |
| mashtree, 1000 genomes | 117 s | 487 MB | 1000-leaf tree |
| sourmash NJ, 100 genomes | 25 s | 170 MB | 100-leaf tree |
| sourmash NJ, 500 genomes | 55 s | 182 MB | 500-leaf tree |
| sourmash NJ, 1000 genomes | 142 s | 294 MB | 1000-leaf tree |
| sibeliaz -> fasttree, 100 genomes | >2 h | — | timeout, no tree |
| sibeliaz -> iqtree, 100 genomes | >2 h | — | timeout, no tree |

Fitting the sourmash NJ curve as linear (sketch/compare) plus cubic (the
pure-Python NJ) gives roughly t = 0.1 s x n + 4.3e-8 s x n^3: about 1.6
hours at n=5000 and about 12 hours at the declared 10000 limit — the
cubic term is ~30 s of the 142 s at n=1000 and dominates beyond ~2000.
mashtree at 5000 and the fasttree/iqtree curve at n=20/50: PENDING.

### Findings

1. **The whole-genome-alignment ML path does not reach 100 genomes on this
   hardware.** Both sibeliaz-based ML cells hit the 2 h timeout at n=100
   (the alignment step dominates; twopaco saturates 8 threads for hours).
   Projects starting from >=100 genomes must dereplicate down or use the
   distance-based builders; the default `dereplicate -> phylo` chain with an
   MSA aligner is effectively bounded by the aligner, not the tree builder.
2. **All aligners project onto a single reference defaulting to
   `genomes[0]`** — the alphabetically first file, in five places (see
   swot-phylo.md for citations) — with no log line. On a clonal set that is
   a clone member. Measured topology effect: PENDING (B4).
3. **The sourmash tree builder is a pure-Python O(n^3) neighbor joining**
   (src/repgenr/tree/newick.py) behind a declared 10000-genome limit; its
   distance is `1 - Jaccard`, which is not an evolutionary distance and
   compresses exactly in the clonal regime (see swot-phylo.md). Measured
   n^3 fit: PENDING.
4. **Near-zero-diversity input produces a degenerate tree with no warning**
   in every path except the `simple` snptyper's zero-SNP guard. Measured:
   PENDING (B5).

## Tool alternatives

Verified maintained alternatives and adapter feasibility (details and
citations in the three SWOT documents):

| Family | Candidate | Why | Adapter effort |
|---|---|---|---|
| treebuilder | VeryFastTree 4.x | drop-in FastTree, vectorized, ~1M-taxon claims | trivial (same CLI family; adapter already anticipates it) |
| treebuilder | decenttree / rapidNJ | C++ NJ from an existing distance matrix; direct fix for the O(n^3) Python NJ | easy (same distance-matrix slot) |
| treebuilder | attotree | faster mashtree reimplementation | trivial (~60-line GENOMES builder) |
| snptyper | ska2 | split-k-mer, reference-free, designed for clonal/outbreak sets; removes reference bias exactly where the current default is weakest | easy (`requires_reference=False`) |
| snptyper | snp-sites | linear SNP-site extraction from any MSA | easy |
| dereplicator | dashing2 / fastANI+clustering | alternative sketch backends | moderate |

## SWOT and gap analysis

Per-stage SWOTs, severity-ranked gap lists, and the full alternatives
matrices, each claim cited to file:line:

- [swot-derep.md](swot-derep.md) — acquisition + dereplication (10 gaps;
  highlights: `--limit` takes the first N in GTDB file order; flat 3600 s
  `datasets` timeout regardless of batch size; no content checksums on
  downloads).
- [swot-phylo.md](swot-phylo.md) — alignment/SNP + trees + tree2tax (17 gaps;
  highlights: five `genomes[0]` reference-default sites; `simple` typer
  silently truncates consensuses to the shortest; Gubbins fed a SNP-only
  alignment; FastTree silently ignores bootstrap/outgroup; tree2tax O(n^2)
  on ladder trees with no zero-length-branch collapse).
- [swot-viral.md](swot-viral.md) — viral chain + plugin surface (17 gaps;
  highlights: the `median_of_medians` over-representation defense is
  deliberate but undocumented and `--length-method mean` silently disables
  it with different semantics per backend; the `S_` outgroup panel is
  download-order dependent; BV-BRC off-by-one admits 4 candidates per taxid
  vs 3 on the records path).

## Recommendations

Quick wins shipping as PRs in this audit series:

1. `fix/scale-diagnostics`: correct the sourmash dense ">5000" message
   (currently prints "~0 GB" from an `:.0f` format); replace the sourmash
   tree builder's declared 10000 limit with the measured value plus a hard
   guard; warn when `--target-reps` cannot converge (achieved vs requested);
   scale the `datasets` download timeout with batch size; preflight
   argv-length warnings for mashtree/sibeliaz/snippy-core.

   the `median_of_medians` rationale (docstring + usage.md); log the

   ARI gap above 0.05.
