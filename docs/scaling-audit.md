# Scaling and bias audit

Status: measurements complete for the full cell matrix (39 cells) and all
four bias experiments (B1, B2, B4, B5). B4 and B5 were run with the
progressivemauve aligner (containerized) after the sibeliaz path proved
unmeasurable at every tested size; raw results are in
`benchmarks/results/bias_b4.json` and `bias_b5.json`.

This document reports, per pipeline step: the available tool alternatives, how
each scales with genome count (measured wall time and peak memory), whether a
project can start from 1000 or 5000 genomes, and how genome similarity
structure — in particular over-represented genotypes such as an outbreak clone
block — biases the results. Methods and raw numbers live in `benchmarks/`
(see `benchmarks/README.md`); mechanism claims cite source locations. The
detailed per-stage SWOT and gap analyses are in [swot-derep.md](swot-derep.md),
[swot-phylo.md](swot-phylo.md), and [swot-viral.md](swot-viral.md).

## Summary: can you start from 1000 / 5000 genomes?

| Step / tool | 1000 genomes | 5000 genomes | Notes |
|---|---|---|---|
| dereplicate: skder | yes (~7 min, 1.1-1.5 GB) | yes (~69 min, 6.4-8.2 GB; 15 min chunked) | ARI 1.0 on both scenarios at every size |
| dereplicate: galah | yes (~4-6 min, 1.2-1.3 GB) | yes (~63 min, 7.4-8.3 GB) | ARI 1.0 on both scenarios at every size |
| dereplicate: sourmash (post-#127) | yes (~1 min, ~0.2 GB) | yes (~5.5 min sparse, ~0.3-0.7 GB) | ARI 1.0 everywhere after the threshold fix |
| dereplicate: chunked (--process-size) | n/a | yes (skder ~15 min, sourmash ~5 min) | ARI 1.0 in both accession orders (B2); only the representative identity is order-dependent |
| phylo: mashtree | yes (~2 min, 0.5 GB) | yes (~53 min, 7.6 GB) | 9 s at n=100 |
| phylo: sourmash NJ | yes (~2.4 min) | extrapolated ~1.5-2 h | pure-Python NJ; measured n^3 fit below |
| phylo: sibeliaz -> fasttree/iqtree | no | no | times out (>1 h) already at n=20 |
| phylo: progressivemauve -> fasttree | not measured | not measured | ~10 min at n=20, ~22 min at n=50 per build (B4/B5 runs, Docker on Rosetta); adapter recommends at most 500 genomes |
| snptype: simple | untested at scale | untested | serial, O(n^2 S) RAM (see swot-phylo) |

## Benchmark design

Synthetic sets generated by `benchmarks/genomegen.py` (seeded, stdlib):

- `balanced_n`: distinct species-level clusters (~95-97 percent inter-cluster
  ANI, 99.5-99.9 percent intra), no over-representation. balanced_100 holds 2
  true clusters; balanced_1000 holds 20.
- `clonal_n`: 40 percent of genomes form one near-identical clone block
  (>=99.99 percent ANI, skani-validated at 99.98-99.99), the rest diverse
  background — the outbreak-plus-context shape.
- Accession order (`clustered` / `interleaved` / `random`) is a first-class
  variable because several selection mechanisms depend on alphabetical
  filename order.

Hardware: 11-core arm64 macOS, 18 GB RAM, 8 threads per run, data on external exFAT
storage. Measured with `/usr/bin/time -l` (max RSS). Caveats: synthetic
genomes are mutated copies of a random 2 Mb ancestor — exact for k-mer/ANI
tools, a lower bound for whole-genome aligners, unrealistic for gene-model
tools. All numbers below are from `benchmarks/results/cells/*.json`.

### Findings

1. **Found and fixed (#127, #128): the sourmash adapter's `--secondary-ani`
   thresholded Jaccard similarity, not ANI.** At the same nominal 0.99
   threshold, skder and galah recovered the true clustering exactly
   (ARI 1.00 in every cell) while sourmash left every genome a singleton on
   the balanced sets (ARI 0.00) and merged only the near-identical clone
   block on the clonal sets (ARI 0.54-0.90). Verified directly: a genome
   pair at 99.57 percent ANI (skani) has k=31 Jaccard 0.796 — far below the
   0.99 cut — while the ANI estimate for the pair is 0.9961. The fix
   converts both back-ends to the ANI scale with one formula: sparse keeps
   pairs by `containment^(1/k)` from branchwater's edge list (prefiltered
   at `threshold^k` to stay sparse), dense converts the Jaccard matrix via
   `(2j/(1+j))^(1/k)` — computed in the adapter rather than with `compare
   --ani`, which reports 0 for tiny sketches. Post-fix, all 12 sourmash
   cells score ARI 1.00 (table above), sparse and dense agree at every
   size, and sourmash-sparse is the fastest correct dereplicator measured
   at n=5000 (335 s, 0.7 GB).
2. **Representative identity is tool- and backend-dependent on clone blocks**
   (B1, `benchmarks/results/bias_b1.json`; clonal_50 under three accession
   orderings). galah crowns the alphabetically first clone member in all
   three orderings — its choice tracks filename sort position exactly.
   sourmash-sparse crowns the alphabetically first member in two of three
   orderings (greedy first-seen assignment). skder picks by its own
   aggregate-ANI criterion (a different member in each ordering; within a
   near-identical clone block that choice is effectively arbitrary). The
   sparse and dense sourmash backends crown different members on the same
   input (clonal_100: g000000 vs g000034; clonal_1000: g000010 vs g000384).
   Practical consequence: which outbreak genome becomes "the representative"
   depends on the tool, the backend, and the accession naming — not on
   content quality.
3. **Chunked dereplication is input-order dependent only in which genome
   becomes the representative, not in the clustering itself (B2).** The
   sorted genome list is sliced into contiguous chunks
   (src/repgenr/stages/dereplicate.py), so chunk composition depends on
   accession order. Measured at n=5000 (clonal set, clustered vs random
   clone placement, skder and sourmash-sparse): all four cells recover the
   truth exactly (ARI 1.00, 61 representatives) — the ARI gap between
   orders is 0.0, far below the 0.05 gate set for adding a
   `--chunk-shuffle` option, so that option is not added. The clone
   block's representative does change with order (skder: g001999 under
   clustered vs g004997 under random; sourmash: g000000 vs g000001) —
   this is the finding-2 representative-identity sensitivity, not a
   clustering-quality effect. Chunking is also the fastest correct way to
   run skder at n=5000: 874 s versus 4127 s single-pass, at 1.1 GB
   versus 8.2 GB.
4. **`--target-reps` bisects a step function on clonal sets.** Intermediate
   targets are unreachable and the search silently returns the closest
   achievable count (max 12 iterations). Pinned by
   `tests/unit/test_bias_regressions.py`.
5. **`--reduce species|genus` keeps the over-represented genotype.** The
   keeper rule (largest existing cluster) selects the clone block's
   representative by construction and folds diverse lineages under it.
   Pinned by `tests/unit/test_bias_regressions.py`.
6. **Memory scales superlinearly with n for skder/galah, confirmed at
   n=5000**: about 200 MB at n=100, 1.1-1.5 GB at n=1000, and 6.4-8.3 GB
   at n=5000 for both tools — a 5x genome increase costs roughly 6x
   memory and 10x wall time. sourmash's sparse path stays nearly flat
   (0.2-0.7 GB across the whole range), and chunking (`--process-size
   1000`) bounds skder to 1.1 GB at n=5000. On this 18 GB machine,
   single-pass skder/galah at n=10000 would be memory-risky; chunked
   skder or sourmash-sparse are the safe paths.

## Phylogeny

### Measured scaling

| Cell | wall | peak RSS | outcome |
|---|---|---|---|
| mashtree, 100 genomes | 9 s | 69 MB | 100-leaf tree |
| mashtree, 1000 genomes | 117 s | 487 MB | 1000-leaf tree |
| mashtree, 5000 genomes | 3153 s | 7611 MB | 5000-leaf tree |
| sourmash NJ, 100 genomes | 25 s | 170 MB | 100-leaf tree |
| sourmash NJ, 500 genomes | 55 s | 182 MB | 500-leaf tree |
| sourmash NJ, 1000 genomes | 142 s | 294 MB | 1000-leaf tree |
| sibeliaz -> fasttree, 20 genomes | >1 h | — | timeout, no tree |
| sibeliaz -> fasttree, 50 genomes | >1 h | — | timeout, no tree |
| sibeliaz -> fasttree, 100 genomes | >2 h | — | timeout, no tree |
| sibeliaz -> iqtree, 20 genomes | >1 h | — | timeout, no tree |
| sibeliaz -> iqtree, 100 genomes | >2 h | — | timeout, no tree |

Fitting the sourmash NJ curve as linear (sketch/compare) plus cubic (the
pure-Python NJ) gives roughly t = 0.1 s x n + 4.3e-8 s x n^3: about 1.6
hours at n=5000 and about 12 hours at the formerly declared 10000 limit —
the cubic term is ~30 s of the 142 s at n=1000 and dominates beyond
~2000. Following this measurement, #129 lowered the builder's advertised
limit to 2000 and added a hard refusal at 5000.

### Findings

1. **The whole-genome-alignment ML path is unmeasurable even at 20 genomes
   on this hardware.** After the n=100 cells hit a 2 h timeout, the ML
   curve was re-sampled at n=20 and n=50 with a 1 h cap — and all three
   cells (fasttree at 20 and 50, iqtree at 20) timed out as well; the
   sibeliaz alignment step dominates before any tree builder runs
   (twopaco saturates 8 threads). Synthetic-genome aligner timings are a
   lower bound (see caveats), but the conclusion holds directionally:
   the `dereplicate -> phylo` chain with an MSA aligner is bounded by the
   aligner, not the tree builder, and is a small-n path for the
   post-dereplication representative set only. The distance-based
   builders are the only measured option beyond ~100 genomes; mashtree
   is confirmed to n=5000 (3153 s, 7.6 GB). The timeout is specific to
   sibeliaz: the B4/B5 runs completed the same path with the
   progressivemauve aligner in about 10 min at n=20 and about 22 min
   per build at n=50 (containerized, fasttree included), so the small-n
   ML path is usable when that aligner is selected.
2. **All aligners project onto a single reference defaulting to
   `genomes[0]`** — the alphabetically first file, in five places (see
   swot-phylo.md for citations). On a clonal set that is a clone member.
   Measured topology effect (B4, mixed 50-genome set, two 25-genome
   truth clusters, progressivemauve + fasttree): swapping the reference
   changes most of the topology. Against the default-reference tree,
   a same-cluster reference swap changes 72 of 94 splits (normalized
   RF 0.77) and a cross-cluster swap changes 68 of 94 (RF 0.72); the
   same-cluster comparison reproduced exactly across two independent
   runs. The deep structure is stable: the bipartition separating the
   two truth clusters is present in all three trees. The instability
   is confined to the shallow, near-clonal part of the tree, where
   branch support is weakest — so within-cluster branching order from
   a single-reference projection alignment should not be
   over-interpreted, and the reference default materially shapes it.
   The mechanism-level mitigation shipped in #130: the auto-selected
   reference is logged loudly in both phylo and snptype. Raw trees and
   RF numbers: `benchmarks/results/bias_b4.json`.
3. **The sourmash tree builder is a pure-Python O(n^3) neighbor joining**
   (src/repgenr/tree/newick.py); its distance is `1 - Jaccard`, which is
   not an evolutionary distance and compresses exactly in the clonal
   regime (see swot-phylo.md). The measured n^3 fit is above; #129
   lowered the advertised limit to the measured 2000 with a hard guard
   at 5000.
4. **Near-zero-diversity input produces a degenerate tree with no warning**
   in every path except the `simple` snptyper's zero-SNP guard. Measured
   (B5, pure-clone n=20 set at 0.005 percent divergence, progressivemauve
   + fasttree): the run completes cleanly and the tree honestly reports
   the near-zero divergence (maximum branch length 5.0e-05). The #130
   low-diversity warning (<10 variable alignment columns) correctly did
   not fire: the 2 Mb alignment still contains 1999 variable columns at
   this divergence, which is real signal rather than noise. The warning
   threshold therefore only catches (near-)identical inputs; that case
   is pinned by unit tests (`tests/unit/test_bias_guards.py`). Raw
   result: `benchmarks/results/bias_b5.json`.

## Tool alternatives

Verified maintained alternatives and adapter feasibility (details and
citations in the three SWOT documents):

| Family | Candidate | Why | Adapter effort |
|---|---|---|---|
| treebuilder | VeryFastTree 4.x | drop-in FastTree, vectorized, ~1M-taxon claims | trivial (same CLI family; adapter already anticipates it) |
| treebuilder | decenttree / rapidNJ | C++ NJ from an existing distance matrix; direct fix for the O(n^3) Python NJ | easy (same distance-matrix slot) |
| treebuilder | attotree | faster mashtree reimplementation | trivial (~60-line GENOMES builder) |
| snptyper | ska2 | split-k-mer, reference-free, designed for clonal/outbreak sets; removes reference bias exactly where the current default is weakest | easy (`requires_reference=False`) |
| snptyper | snp-sites | linear SNP-site extraction from any MSA | easy |
| dereplicator | dashing2 / fastANI+clustering | alternative sketch backends | moderate |

## SWOT and gap analysis

Per-stage SWOTs, severity-ranked gap lists, and the full alternatives
matrices, each claim cited to file:line:

- [swot-derep.md](swot-derep.md) — acquisition + dereplication (10 gaps;
  highlights: `--limit` takes the first N in GTDB file order; flat 3600 s
  `datasets` timeout regardless of batch size; no content checksums on
  downloads).
- [swot-phylo.md](swot-phylo.md) — alignment/SNP + trees + tree2tax (17 gaps;
  highlights: five `genomes[0]` reference-default sites; `simple` typer
  silently truncates consensuses to the shortest; Gubbins fed a SNP-only
  alignment; FastTree silently ignores bootstrap/outgroup; tree2tax O(n^2)
  on ladder trees with no zero-length-branch collapse).
- [swot-viral.md](swot-viral.md) — viral chain + plugin surface (17 gaps;
  highlights: the `median_of_medians` over-representation defense is
  deliberate but undocumented and `--length-method mean` silently disables
  it with different semantics per backend; the `S_` outgroup panel is
  download-order dependent; BV-BRC off-by-one admits 4 candidates per taxid
  vs 3 on the records path).

## Recommendations

Quick wins shipped as PRs in this audit series (all merged):

1. #127/#128 `fix/sourmash-ani-threshold` + e2e recalibration: the
   finding-1 correctness fix.
2. #129 `fix/scale-diagnostics`: corrected the sourmash dense ">5000"
   message (previously printed "~0 GB" from an `:.0f` format); replaced
   the sourmash tree builder's declared 10000 limit with the measured
   2000 plus a hard guard at 5000; warns when `--target-reps` cannot
   converge (achieved vs requested); scales the `datasets` download
   timeout with batch size; preflight argv-length warnings for
   mashtree/sibeliaz/snippy-core.
3. #130 `fix/bias-guards`: warns on near-zero informative sites in phylo;
   documents the `median_of_medians` rationale (docstring + usage.md);
   logs the reference-genome choice loudly in phylo and snptype.

Decision recorded: no `--chunk-shuffle` option. The gate was an ARI gap
above 0.05 between accession orders in B2; the measured gap is 0.0
(both orders ARI 1.00 for both skder and sourmash at n=5000).

Backlog (larger items, report-only): decenttree/rapidNJ NJ replacement, ska2
snptyper adapter (the B4 result strengthens this case: a reference-free
snptyper removes the measured reference sensitivity exactly where it is
largest), VeryFastTree adapter, quality-aware representative selection
(finding 2 — the highest-value remaining item), stratified `--limit`
sampling, distance-aware bacterial outgroup selection, and `S_`-panel
diversification in the viral outgroup.
